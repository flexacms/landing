An agency that builds websites for several clients has two problems. Each client's content has to stay separate, and the client needs to review changes without being able to break things. Sharing one account with everyone solves neither.

Flexa gives every project its own workspace. Models, entries, media, members and API keys belong to one workspace, and nothing is shared between them.

## 1. One workspace per client

Create a workspace for each client, and start it from a template when it fits: a blog, a product catalog or a marketing site. Each one starts with models and sample entries you can change.

## 2. Assign roles on purpose

Each workspace has owners, admins, editors and viewers. Give each person the role that matches their job: editors write, and viewers are for clients who should review content without changing it.

## 3. One API key per site

Each client's website gets its own key, with only the abilities it needs. A marketing site usually needs read access. Set an expiry date so a key doesn't stay active after the project ends.

## 4. Offboarding a client

When a contract ends, revoke that workspace's keys and remove the members. Nothing in the other workspaces changes, because they never shared keys or content.

## Why this matters for your business

Each client's content, team and keys are isolated in their own workspace. A mistake in one project doesn't touch another, and the revision history lets you restore an earlier version if a client asks about a change.
